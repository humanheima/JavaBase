# 快速排序（Quick Sort）解题文档

## 一、题目描述

给定一个整型数组，将其**原地**升序排序。

快速排序是一种基于**分治法（Divide and Conquer）**的比较排序，是工程中最常用的内排序之一（Java 的 `Arrays.sort(int[])` 底层即采用其改进版双轴快排）。

**示例：**

| 输入 | 输出 | 说明 |
|------|------|------|
| `{8, 4, 9, 1, 10, 6}` | `{1, 4, 6, 8, 9, 10}` | 升序 |
| `{5, 5, 3, 8, 3, 1}` | `{1, 3, 3, 5, 5, 8}` | 含重复元素 |
| `{5, 4, 3, 2, 1}` | `{1, 2, 3, 4, 5}` | 逆序输入 |

---

## 二、核心观察

1. **一次分区确定一个元素的最终位置**：选定基准 `pivot` 后，把小于它的放左、大于它的放右，分区结束后 `pivot` 所在下标就是它在最终有序数组中的下标，**之后永不移动**。
2. **递归只处理子区间**：对基准左、右两段分别重复分区即可，无需合并（与归并排序最大的区别——快排「分」的时候做功，归并「合」的时候做功）。
3. **基准的选取决定性能**：每次分区若能把数组对半分，递归深度为 `O(log n)`，总复杂度 `O(n log n)`；若基准总是最大/最小值（如对已排序数组取首元素为基准），递归退化成 `O(n)` 层，复杂度恶化为 `O(n^2)`。**随机化基准**可在概率上规避此最坏情况。
4. **快排不稳定**：分区时的跨距离交换会改变相等元素的相对次序。

---

## 二·补、基准最终停在哪里？是固定的吗

这是初学快排最容易绕进去的一点，要分两层理解「固定」：

### （1）分区结束后，基准就「永久不动」—— 是固定的

每趟 `partition` 走完，基准落到的下标，就是它在**最终有序数组里的下标**，之后所有递归都不会再碰它。这正是快排的核心机制：

```java
arr[low] = pivot;   // low == high，基准归位
return low;          // 返回的下标，就是基准的「终身位置」
```

返回后递归只处理 `[low, pivotIndex-1]` 和 `[pivotIndex+1, high]`，基准被夹在中间不再参与——**一次分区 = 确定一个元素的最终位置**。

### （2）但「停在第几格」事先不固定 —— 由比它小的元素个数决定

> 基准的最终下标 = 本区间内比它小的元素个数 + low

以 `{8, 4, 9, 1, 10, 6}`、基准取 `8` 为例：比 8 小的有 `4, 1, 6` 共 3 个，所以 8 最终停在下标 `0 + 3 = 3`：

```
分区后:  [6, 4, 1, 8, 10, 9]
                   ↑ 基准 8 停在下标 3，从此不动
```

换一个数组，比基准小的个数不同，停的位置就不同。所以位置不是预先定好的常量，而是「这一趟数下来」的结果。

| 问法 | 答案 |
|------|------|
| 基准停下后还会再动吗？ | 不会，**永久固定**在最终有序位置 |
| 停在哪个下标是预先定好的吗？ | 不是，由「比它小的元素个数」决定 |

> 也正因为每趟只保证**基准**到位、两边内部仍无序，才需要递归继续排两边。这与冒泡「每趟把最大值顶到末尾」思路相似，但快排一趟就把数组劈成两半，递归深度仅 `O(log n)`，因此远快于冒泡。

## 三、三种解法

### 解法一：挖坑法（推荐，本仓库主写法）

**思路：**
1. 取最左元素 `arr[low]` 作为基准，此位置视为一个「空坑」。
2. 右指针 `high` 从右向左找到第一个 `< pivot` 的元素，填入左坑，`high` 变成新坑。
3. 左指针 `low` 从左向右找到第一个 `> pivot` 的元素，填入右坑，`low` 变成新坑。
4. 两指针相遇时把基准放回该坑，返回其下标，再递归左右子区间。

```java
public static void quickSort(int[] arr, int low, int high) {
    if (low < high) {
        int pivotIndex = partition(arr, low, high);
        quickSort(arr, low, pivotIndex - 1);
        quickSort(arr, pivotIndex + 1, high);
    }
}

private static int partition(int[] arr, int low, int high) {
    int pivot = arr[low];
    while (low < high) {
        while (low < high && arr[high] >= pivot) high--;
        arr[low] = arr[high];          // 小的填到左坑
        while (low < high && arr[low] <= pivot) low++;
        arr[high] = arr[low];          // 大的填到右坑
    }
    arr[low] = pivot;                  // 基准归位
    return low;
}
```

- **时间复杂度：** 平均 `O(n log n)`，最坏 `O(n^2)`
- **空间复杂度：** `O(log n)`（递归栈，平均情形）
- **优点：** 交换次数少（用赋值代替三次交换），常数小
- **缺点：** 取固定首元素为基准，面对有序/近乎有序输入会退化

> **易错点**：内层 `while` 的比较必须分别用 `>=` 和 `<=`（含等号），否则遇到与基准相等的元素时指针不前进，会死循环。

---

### 解法二：Lomuto 分区

**思路：**
1. 取最右元素 `arr[high]` 作为基准。
2. 用慢指针 `i` 标记「小于基准区」的右边界，快指针 `j` 遍历 `[low, high)`。
3. 每遇到一个 `< pivot` 的元素，`i++` 并与 `arr[j]` 交换，把它纳入小于区。
4. 遍历结束把基准与 `arr[i+1]` 交换归位，返回 `i+1`。

```java
private static int partitionLomuto(int[] arr, int low, int high) {
    int pivot = arr[high];
    int i = low - 1;
    for (int j = low; j < high; j++) {
        if (arr[j] < pivot) {
            i++;
            swap(arr, i, j);
        }
    }
    swap(arr, i + 1, high);
    return i + 1;
}
```

- **时间复杂度：** 平均 `O(n log n)`，最坏 `O(n^2)`
- **空间复杂度：** `O(log n)`
- **优点：** 逻辑直观、单向遍历，易于记忆和实现，是教材常见写法
- **缺点：** 交换次数比挖坑法多；对含大量重复元素的数组同样会退化

---

### 解法三：随机化基准

**思路：** 在 `[low, high]` 内随机挑一个下标与 `low` 交换，再复用挖坑法分区。把「最坏输入」从某种固定形态变成概率极低的事件，从而在期望意义上稳定 `O(n log n)`。

```java
public static void quickSortRandom(int[] arr, int low, int high) {
    if (low < high) {
        int randomIndex = low + (int) (Math.random() * (high - low + 1));
        swap(arr, low, randomIndex);
        int pivotIndex = partition(arr, low, high);
        quickSortRandom(arr, low, pivotIndex - 1);
        quickSortRandom(arr, pivotIndex + 1, high);
    }
}
```

- **时间复杂度：** 期望 `O(n log n)`，最坏仍是 `O(n^2)`（但概率极低）
- **空间复杂度：** `O(log n)`
- **优点：** 有效防止对有序数组退化，工程实践首选思路之一
- **缺点：** 引入随机数有少量额外开销；对「全部相等」的数组仍无能为力（需三路快排解决）

## 四、三种解法对比

| 解法 | 基准选取 | 分区方式 | 平均时间 | 最坏时间 | 空间 | 适用场景 |
|------|----------|----------|----------|----------|------|----------|
| 一、挖坑法 | 最左元素 | 双指针填坑 | `O(n log n)` | `O(n^2)` | `O(log n)` | 通用，交换少 |
| 二、Lomuto | 最右元素 | 慢/快指针 | `O(n log n)` | `O(n^2)` | `O(log n)` | 教学、易实现 |
| 三、随机化 | 随机元素 | 双指针填坑 | `O(n log n)` | `O(n^2)`（罕见） | `O(log n)` | 防有序退化 |

---

## 五、易错点总结

1. **死循环**：挖坑法内层比较必须带等号（`>=` / `<=`），否则相等元素会卡住指针。
2. **递归边界**：递归对子区间应为 `[low, pivotIndex-1]` 与 `[pivotIndex+1, high]`，**不要把 `pivotIndex` 再纳入递归**，否则无法收敛甚至栈溢出。
3. **入口条件**：`if (low < high)` 必不可少，它同时处理了空区间和单元素区间的递归终止。
4. **最坏退化**：对已排序数组用固定首/尾元素为基准会退化成 `O(n^2)`，必要时用随机化或三数取中。
5. **大量重复元素**：普通快排对「大片相等」的数组依然退化，根治需用**三路快排（荷兰国旗划分）**。
6. **稳定性**：快排不稳定，若要求保持相等元素相对顺序，应选归并排序。

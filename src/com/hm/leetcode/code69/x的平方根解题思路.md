# LeetCode 69. x 的平方根（Sqrt(x)）解题文档

## 一、题目描述

给你一个非负整数 `x`，计算并返回 `x` 的算术平方根。由于返回类型是整数，结果**只保留整数部分**，小数部分将被舍去（即向下取整）。

注意：不允许使用任何内置指数函数和算符，例如 `pow(x, 0.5)` 或 `x ** 0.5`。

**示例：**

| 输入 | 输出 | 说明 |
|------|------|------|
| `4` | `2` | √4 = 2 |
| `8` | `2` | √8 = 2.828…，向下取整为 2 |
| `0` | `0` | √0 = 0 |
| `1` | `1` | √1 = 1 |

**链接：** https://leetcode.cn/problems/sqrtx/

---

## 二、核心观察

1. 题目本质：求满足 **`k * k <= x` 的最大整数 `k`**。
2. **单调性**：随着 `k` 增大，`k * k` 单调递增，因此答案区间具有单调性 → 可二分。
3. **溢出陷阱**：`x` 最大可达 `2147483647`（`Integer.MAX_VALUE`），其平方根约为 `46340`。在比较 `mid * mid <= x` 时，`mid * mid` 会超出 `int` 范围，**必须转成 `long` 再相乘**，否则溢出导致误判。
4. 当 `x >= 2` 时，`√x <= x / 2`，二分右边界取 `x / 2` 即可，缩小搜索范围。

---

## 三、三种解法

### 解法一：暴力枚举

**思路：**
1. 从 `i = 0` 开始递增。
2. 找到第一个满足 `i * i > x` 的 `i`，那么 `i - 1` 就是答案。
3. `i` 用 `long` 防止 `i * i` 溢出。

```java
public static int mySqrtBruteForce(int x) {
    long i = 0;
    while (i * i <= x) {
        i++;
    }
    return (int) (i - 1);
}
```

- **时间复杂度：** O(√x)
- **空间复杂度：** O(1)
- **优点：** 思路最直白
- **缺点：** 当 `x` 很大时（如 `INT_MAX`）需循环约 4.6 万次，效率最低

---

### 解法二：二分查找（推荐）

**思路：**
1. `x < 2` 时直接返回 `x`（0 和 1 的平方根是自身）。
2. 在 `[1, x/2]` 上二分，查找满足 `mid * mid <= x` 的**最大** `mid`。
3. 若 `mid * mid <= x`，`mid` 可能是答案，记录后往右半区继续找更大值；否则收缩右边界。
4. 比较时 `(long) mid * mid` 防溢出。

```java
public static int mySqrt(int x) {
    if (x < 2) {
        return x;
    }
    int left = 1, right = x / 2, answer = 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if ((long) mid * mid <= x) {
            answer = mid;
            left = mid + 1;
        } else {
            right = mid - 1;
        }
    }
    return answer;
}
```

- **时间复杂度：** O(log x)
- **空间复杂度：** O(1)
- **优点：** 效率高、写法稳健，是工程与面试首选
- **缺点：** 需要注意边界（`left <= right`、`mid` 取法、溢出）

> **为什么 `left` 从 1 开始而不是 0？**
> 因为前面已经用 `if (x < 2) return x;` 把「答案为 0 或 1」的情况（`x = 0`、`x = 1`）提前返回了。能走到二分的一定是 `x >= 2`，而 `x >= 2` 时 `√x >= √2 ≈ 1.41`，向下取整至少是 1，**0 不可能是结果**，所以从 1 起步即可，省去一次无意义的判断。`answer` 也因此初始化为 `1`（在 `x >= 2` 前提下 `1 * 1 <= x` 恒成立，是安全下界）。
>
> 注意这是和特判**配套**的：若删掉 `if (x < 2)`，则 `left` 必须能覆盖 0、1（否则 `x = 0` 时 `right = x/2 = 0`，循环 `left(1) <= right(0)` 不成立，会错误返回初值）。从 0 开始本身不会错，只是多一次循环，属于小优化而非正确性问题。

---

### 解法三：牛顿迭代法

**思路：**
1. 求方程 `f(t) = t² - x = 0` 的正根。
2. 迭代公式（用 `f` 在 `t` 处的切线与 x 轴交点逼近）：`t = (t + x / t) / 2`。
3. 当 `t * t <= x` 时收敛停止，取整数部分。
4. 初值取 `t = x`，从上方单调递减逼近 `√x`。

```java
public static int mySqrtNewton(int x) {
    if (x == 0) {
        return 0;
    }
    double t = x;
    while (t * t > x) {
        t = (t + x / t) / 2;
    }
    return (int) t;
}
```

- **时间复杂度：** O(log x)，收敛速度极快（二次收敛）
- **空间复杂度：** O(1)
- **优点：** 迭代次数最少，理论效率最优
- **缺点：** 依赖浮点运算，需理解迭代原理；浮点精度需谨慎处理

---

## 四、三种解法对比

| 解法 | 核心思路 | 时间 | 空间 | 优点 | 缺点 |
|------|----------|------|------|------|------|
| 一、暴力枚举 | 逐个累加直到平方超过 x | O(√x) | O(1) | 直白 | 大数慢 |
| 二、二分查找 | 在 [1, x/2] 上二分逼近 | O(log x) | O(1) | 稳健高效 | 边界细节多 |
| 三、牛顿迭代 | 切线逼近方程正根 | O(log x) | O(1) | 收敛最快 | 依赖浮点精度 |

---

## 五、易错点总结

1. **整数溢出**：`mid * mid`、`i * i` 在 `x` 接近 `INT_MAX` 时会溢出，必须用 `long`。这是本题最大的坑。
2. **边界 `x = 0 / 1`**：二分法要先特判 `x < 2`，否则 `right = x / 2 = 0` 会漏掉答案。
3. **二分写法**：循环条件用 `left <= right`，`mid` 用 `left + (right - left) / 2` 防溢出，命中后用 `ans` 暂存再继续右探，避免漏掉最大值。
4. **牛顿法初值与停止条件**：初值取 `x`（从上方逼近），用 `t * t > x` 作为继续迭代的条件，收敛后强转 `int` 自然向下取整。

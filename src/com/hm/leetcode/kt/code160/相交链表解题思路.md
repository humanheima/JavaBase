# LeetCode 160. 相交链表（Intersection of Two Linked Lists）解题文档

## 一、题目描述

给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个单链表相交的**起始节点**。如果两个链表不存在相交节点，返回 `null`。

注意：相交指的是**节点引用相同**（同一个对象），而不是节点的值 `val` 相等。

**示例：**

| 输入 | 输出 | 说明 |
|------|------|------|
| A: `4→1→8→4→5`，B: `5→6→1→8→4→5`（从 `8` 起共享） | 相交节点 `8` | 两链表从节点 `8` 开始为同一段 |
| A: `1→2`，B: `3→4`（无公共节点） | `null` | 不相交 |

**链接：** https://leetcode-cn.com/problems/intersection-of-two-linked-lists/

---

## 二、核心观察

1. **比较的是引用而非值**：判断相交要看是否是同一个节点对象（Kotlin 中用 `===`），不能只看 `val` 相等。
2. **相交后必然“尾部共享”**：两个单链表一旦相交，从相交点到链尾完全重合，长度相同；差异只在相交点之前的部分。
3. **消除长度差是关键**：两链表头到相交点的距离可能不同，只要想办法让两个指针“对齐”到距相交点等距的位置，就能同步相遇。

---

## 三、两种解法

### 解法一：HashSet 记录法

**思路：**
1. 遍历链表 A，把每个**节点对象**放入 `HashSet`。
2. 遍历链表 B，第一个已存在于集合中的节点即为相交起点。
3. 遍历完 B 都没命中则返回 `null`。

```kotlin
fun getIntersectionNode(headA: ListNode?, headB: ListNode?): ListNode? {
    val visited = HashSet<ListNode>()
    var temp = headA
    while (temp != null) {
        visited.add(temp)
        temp = temp.next
    }
    temp = headB
    while (temp != null) {
        if (temp in visited) {
            return temp
        }
        temp = temp.next
    }
    return null
}
```

- **时间复杂度：** O(m + n)，m、n 为两链表长度
- **空间复杂度：** O(m)，需存下链表 A 的所有节点
- **优点：** 思路直观，易写易懂
- **缺点：** 需要额外 O(m) 空间

---

### 解法二：双指针法（推荐，空间 O(1)）

**思路：**
1. 指针 `pA` 从 A 头出发，`pB` 从 B 头出发，同步前进。
2. `pA` 走到 A 末尾后改从 B 头继续，`pB` 走到 B 末尾后改从 A 头继续。
3. 这样两个指针走过的总路程相等（都是 `m + n`），若相交会在相交点相遇；若不相交则会同时走到 `null` 退出。

> 直觉：A 段长 a + 公共段 c，B 段长 b + 公共段 c。`pA` 走 `a + c + b`，`pB` 走 `b + c + a`，两者在第二轮的相交点对齐相遇。

```kotlin
fun getIntersectionNodeTwoPoint(headA: ListNode?, headB: ListNode?): ListNode? {
    if (headA == null || headB == null) return null

    var pA: ListNode? = headA
    var pB: ListNode? = headB

    // 循环直到 pA === pB（相交节点或同时为 null）
    while (pA !== pB) {
        pA = if (pA == null) headB else pA.next
        pB = if (pB == null) headA else pB.next
    }
    return pA
}
```

- **时间复杂度：** O(m + n)
- **空间复杂度：** O(1)
- **优点：** 不占额外空间，写法简洁优雅
- **缺点：** “换头继续走”的等长原理需要理解

## 四、两种解法对比

| 解法 | 核心思路 | 时间 | 空间 | 优点 | 缺点 |
|------|----------|------|------|------|------|
| 一、HashSet | 存 A 的节点，遍历 B 找命中 | O(m+n) | O(m) | 直观 | 额外空间 |
| 二、双指针 | 换头走，消除长度差后相遇 | O(m+n) | O(1) | 省空间、优雅 | 原理需理解 |

## 五、易错点总结

1. **比较引用而非值**：必须判断同一个节点对象（Kotlin 用 `===` / `!==`，集合 `contains` 依赖 `ListNode` 的默认引用语义）；不要写成 `val` 相等。
2. **退出条件**：双指针法里 `pA !== pB` 要用引用不等；当两链表不相交时，两指针会同时变 `null`，此时 `pA === pB === null`，循环正确退出并返回 `null`。
3. **不要在指针为 null 时取 `.next`**：要先判 `pA == null` 再决定换头还是 `pA.next`，否则空指针。
4. **Kotlin 互操作小坑**：`ListNode` 的字段名 `val` 是 Kotlin 关键字，访问时需加反引号写成 `节点.\`val\``。

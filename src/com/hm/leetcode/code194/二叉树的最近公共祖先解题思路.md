# LCR 194. 二叉树的最近公共祖先 解题文档

## 一、题目描述

给定一棵二叉树，找出树中两个指定节点 `p`、`q` 的**最近公共祖先**（LCA, Lowest Common Ancestor）。

最近公共祖先定义为：对于有根树的两个节点 `p`、`q`，LCA 是这样一个节点 `x`——`x` 同时是 `p` 和 `q` 的祖先，且 `x` 的**深度尽可能大**。注意：**一个节点也可以是它自己的祖先**。

约束：

- 所有节点的值互不相同；
- `p`、`q` 均存在于给定的二叉树中。

**示例**（基于下面这棵树）：

```
           3
         /   \
        5     1
       / \   / \
      6   2 0   8
         / \
        7   4
```

| 输入 (p, q) | 输出 | 说明 |
|-------------|------|------|
| `(5, 1)` | `3` | 5、1 分居根的两侧 |
| `(5, 4)` | `5` | **5 是 4 的祖先**，节点可以是自身的祖先 |
| `(7, 4)` | `2` | 同属节点 2 的子树 |
| `(6, 8)` | `3` | 跨越整棵树 |

**链接：** https://leetcode.cn/problems/er-cha-shu-de-zui-jin-gong-gong-zu-xian-lcof/

---

## 二、核心观察

1. **LCA 的判定特征：** 对节点 `root`，若 `p`、`q` **分别**位于它的左、右子树，则 `root` 就是 LCA；若两者都在同一侧，答案一定在那一侧更深处。
2. **“祖先含自身”是关键边界。** 当 `p` 本身就是 `q` 的祖先（如 `LCA(5,4)`），答案就是 `p`。递归解法靠出口 `root == p || root == q` 命中后直接上抛来覆盖这种情况——**这一句不能省**。
3. **本题与普通二叉树 LCA（LeetCode 236 / code236 叶子版）是同一问题。** 区别仅在于这里 `p`、`q` 是任意节点，不限定为叶子。

---

## 三、两种解法

### 解法一：递归后序遍历（推荐）

**思路：**

定义 `lowestCommonAncestor(root, p, q)`：在以 `root` 为根的子树中查找 `p`、`q`，返回其 LCA；若都不在则返回 `null`。

1. **出口：** `root` 为空，或 `root` 命中 `p` / `q`，直接返回 `root`。
2. 在左、右子树分别递归，得到 `left`、`right`。
3. 若 `left`、`right` **都非空** —— `p`、`q` 分居两侧，`root` 即 LCA。
4. 否则返回非空的一侧上抛（两目标同侧，或都不在）。

**关键代码：**

```java
public static TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) {
        return root;
    }
    TreeNode left = lowestCommonAncestor(root.left, p, q);
    TreeNode right = lowestCommonAncestor(root.right, p, q);
    if (left != null && right != null) {
        // p、q 分居 root 两侧，当前 root 就是最近公共祖先
        return root;
    }
    return left != null ? left : right;
}
```

- **时间复杂度：** O(n)，每个节点访问一次。
- **空间复杂度：** O(h)，递归栈深度，`h` 为树高，最坏（链状）退化为 O(n)。
- **优点：** 一遍遍历、代码极简、无需额外结构，是面试首选。
- **缺点：** 自底向上回溯逻辑初看不够直观。

---

### 解法二：父指针 + 哈希表

**思路：**

1. 一次遍历，用哈希表记录每个节点的 **“子 → 父”** 映射。
2. 从 `p` 出发沿父链一路向上，把途经节点（含 `p` 自身）放入 `visited` 集合——这就是 `p` 的全部祖先。
3. 从 `q` 出发沿父链向上，**第一个出现在 `visited` 中的节点**就是 LCA。

**关键代码：**

```java
public static TreeNode lowestCommonAncestorByParent(TreeNode root, TreeNode p, TreeNode q) {
    Map<TreeNode, TreeNode> parent = new HashMap<>();
    parent.put(root, null);
    buildParent(root, parent);

    Set<TreeNode> visited = new HashSet<>();
    for (TreeNode cur = p; cur != null; cur = parent.get(cur)) {
        visited.add(cur);            // p 的祖先链（含自身）
    }
    for (TreeNode cur = q; cur != null; cur = parent.get(cur)) {
        if (visited.contains(cur)) { // q 上溯遇到的第一个公共祖先
            return cur;
        }
    }
    return null;
}
```

- **时间复杂度：** O(n)。
- **空间复杂度：** O(n)，父指针映射 + visited 集合。
- **优点：** 思路直观；父指针一旦建好，可处理多次查询，也便于改造成“只给两个节点、能向上访问父指针”的变体。
- **缺点：** 需要额外 O(n) 空间。

## 四、两种解法对比

| 解法 | 核心思路 | 时间 | 空间 | 优点 | 缺点 |
|------|----------|------|------|------|------|
| 一、递归后序 | 自底向上，左右各命中一个则当前是 LCA | O(n) | O(h) | 一遍、极简、省空间 | 回溯逻辑不直观 |
| 二、父指针+哈希 | 记录父节点，p 标祖先链，q 上溯找首个公共点 | O(n) | O(n) | 直观、可多次查询 | 额外 O(n) 空间 |

## 五、易错点总结

1. **“祖先含自身”不可漏。** 递归出口里的 `root == p || root == q` 既是终止条件，也负责处理“一个节点是另一个的祖先”的情形，删掉会得到错误答案。
2. **比较用引用而非值。** 题目虽保证值互不相同，但实现上仍应以节点对象（`==`）为准，避免对“值可能重复”的扩展场景埋雷。
3. **父指针映射要含根。** `parent.put(root, null)` 作为上溯终点，否则 `parent.get(root)` 取不到值会出错或死循环。
4. **空树。** `root` 为空直接返回 `null`，保留递归出口即可。
5. **题目保证 p、q 存在。** 若不保证，递归解法需改为额外记录“是否真的找到两者”，否则当某节点不存在时可能误返回另一个节点。
